# Tâche 2.2 — Langues, adresses traduites, cookies
Date : 2026-11-07 · Phase 2 · Statut : rapportée

## En une phrase
Le site existe en français et en anglais, avec des adresses traduites (`/fr/commander`, `/en/order`), et retient la langue et la devise choisies.

## Ce qui a été fait
- `next-intl` branché (`src/i18n/*`, `src/proxy.ts`) : au premier passage, la langue du navigateur décide ; le choix est ensuite gardé.
- Adresses traduites selon `LLD §6`.
- Devises XAF, XOF, USD ; devise inconnue = XAF ; XAF en entier, sans décimales. Taux fictif de démonstration (le vrai taux vient en phase 4).
- `fr.json` et `en.json` ont exactement les mêmes clés (un test le vérifie).
- Après les contrôles : le cookie de devise s'appelle `lp_currency`.

## Vérifications (résultats réels)
- Tests `routing`, `locale-detection`, `currency`, `currency-cookie`, `messages` : verts, dans les 247 tests Vitest.
- Lint, types, build : OK.

## Corrections demandées puis faites
- Cookie de devise renommé `lp_currency` ; pages d'attente pour toutes les adresses (voir 2.5).

## Fichiers modifiés
- `src/i18n/{routing,request,navigation,detect-locale}.ts`, `src/proxy.ts`, `src/lib/currency.ts`, `src/messages/{fr,en}.json`, `next.config.ts`
- Tests : `tests/unit/{routing,locale-detection,currency,currency-cookie,messages}.test.ts`

## Ce que tu peux tester toi-même
1. Ouvre `/fr/demo`, change la langue : tu arrives sur `/en/demo`.
2. Change la devise (XAF, XOF, USD), recharge la page : le choix est gardé.
