## Ce que chaque groupe prouve
- Accès : `/admin` et toute autre adresse = 404 ; seule l'adresse `ADMIN_PATH` (sensible à la casse, jamais si la variable est vide) ouvre la page ; visiteur, client (même en aal2), client bloqué = 404 (jamais 403) ; admin avec facteur TOTP mais sans code = 401 MFA_REQUIRED ; admin sans facteur = 404 ; code à 6 chiffres exigé (5, 7 chiffres, lettres, nombre, vide, null = 400, Supabase jamais appelé) ; le code du 2e appareil est accepté ; 5 mauvais codes = alerte Telegram sans le code ; session 12 h (fonction pure + `timebox = "12h"` dans `supabase/config.toml`) ; TOTP activé dans la config ; robots.txt et sitemap ne citent pas l'adresse ; seules les routes admin importent `src/server/admin`.
- Stats : ventes, bénéfice (prix payé moins coût × taux), nombre de commandes, recharges, nouveaux clients, pays, sur 3 fenêtres ; commandes remboursées exclues ; recharges échouées ou en attente exclues ; solde fournisseur 4,99 $ = alerte, 5,00 $ = pas d'alerte ; seuil lu dans les réglages ; tous les montants entiers ; plage inconnue = 400.
- Clients : recherche par email, téléphone, code de parrainage ; caractères spéciaux (`%`, `,`, `)`, `'`) traités comme du texte ; pagination sans doublon ; fiche complète ; blocage exige un motif ; débloquer efface le motif ; statut `deleted`/`admin` refusé ; compte admin non bloquable ; remise 0..50 ; plafond entier ≥ 0 ; champs inconnus (`is_admin`, `balance_xaf`, `referred_by`) refusés ; un profil modifié ne bouge jamais le solde ; client bloqué ne peut plus commander (ACCOUNT_BLOCKED), remise de 20 % = 1 000 XAF deviennent 800 XAF, plafond abaissé = DAILY_LIMIT_REACHED ; notes privées illisibles par le client ; audit écrit à chaque modification.
- Bonus de parrainage annulé : 150 → 0 ; solde 50 → -100 XAF (décision du propriétaire) ; -100 XAF = commande refusée (INSUFFICIENT_BALANCE) ; après recharge de 1 000 XAF = 900 XAF et commande possible ; double annulation et 3 annulations simultanées = un seul retrait ; NOT_ADMIN, REWARD_NOT_FOUND, NOTE_REQUIRED ; le client ne peut pas appeler la fonction ; la fiche affiche la dette (100 XAF).
- Signal même IP : vrai seulement si les deux empreintes sont connues et égales ; jamais d'IP ni d'empreinte dans la réponse ; le bonus reste versé et le filleul reste actif (aucun blocage).
- Borne `referral_pct` : 0, 5, 12,5, 100 acceptés ; -1, 100,01, 101, texte, tableau, objet refusés par la base, valeur inchangée.
- Limite de messages : 3 d'affilée, le 4e refusé en base (`MESSAGE_LIMIT_REACHED`), valable par chemin client connecté ; la réponse du propriétaire remet à zéro ; propre à chaque ticket et chaque client ; 6 messages en parallèle = 3 acceptés ; service = RATE_LIMITED 429 `unanswered_messages` ; 3 alertes Telegram et aucune pour le message refusé, sans texte.
- Défaut D : `<uid>/<uuid>.(png|jpg|webp)` seul accepté ; remontée de dossier, sous-dossier, nom non uuid, extension exe, double extension, majuscules, retour à la ligne refusés.
- Purge : liste sans suppression ; délai de grâce 60 min ; `confirm` doit être exactement `true` ; chemins invalides = toute la demande refusée ; fichier rattaché protégé ; fichier absent ignoré ; audit ; jamais appelée par un cron.
- E2E : 404 sur `/admin`, `/fr/admin`, `/en/admin`, `/wp-admin`…, 404 sans redirection sur les pages internes, 404 API sans session, page de connexion visible à l'adresse secrète avec noindex/nofollow (en-tête et balise), mauvais mot de passe = message neutre, adresse absente de robots.txt, sitemap et accueil.

## Points ambigus ou contradictoires (à trancher, rien deviné de façon silencieuse)
1. **Plage des stats** : `API_SPEC §8` dit `?from=&to=`, la décision du propriétaire dit « pas de dates libres ». J'ai testé `?range=today|7d|30d`. À confirmer, puis corriger `API_SPEC.md`/`openapi.yaml`.
2. **Fuseau de « aujourd'hui »** : non précisé. Les tests évitent la frontière (lignes à 12 h UTC, hier à plus de 24 h). Le coder doit choisir (UTC+1 conseillé).
3. **Admin en aal1 sans facteur TOTP** : le texte dit « 404 pour admin sans aal2, MFA_REQUIRED seulement quand il faut le code ». J'ai lu : facteur existant = 401 MFA_REQUIRED, aucun facteur = 404 sur les routes de données. Les routes d'enrôlement des 2 appareils (`/admin/mfa/*` autres que `verify`) **ne sont pas dans API_SPEC §8** : seuls `mfaSetupStatus` (pur) et `verify` sont testés. À spécifier.
4. **Mauvais code à 6 chiffres** : aucun code d'erreur dédié dans `API_SPEC §3`. J'ai utilisé 401 MFA_REQUIRED. Alerte à 5 échecs : événement Telegram `admin_login_failed` (nouveau nom, à ajouter à `OwnerEvent`).
5. **« Même téléphone »** : `profiles.phone` est UNIQUE, deux comptes ne peuvent donc pas avoir le même téléphone. Seul « même IP » est testable (colonne `profiles.signup_ip_hash`, empreinte HMAC via `hashIp`, jamais l'IP). Le signal « téléphone » n'a pas de sens tel quel : à reformuler ou abandonner.
6. **Solde négatif** : `wallets.balance_xaf >= 0` et `wallet_transactions.balance_after_xaf >= 0` (et `schema.test.ts:156`, qui exige qu'un solde de -1 soit refusé) contredisent la décision. Je n'ai pas touché ce test existant. lp-db doit assouplir les deux contraintes **sans** rouvrir l'écriture directe (idéalement : seule `cancel_referral_bonus` peut descendre sous zéro) ; le test `schema.test.ts:156` devra être adapté sur décision du chef de projet.
7. **Limite des 3 messages** : « par ticket » (testé) ou « par client tous tickets confondus » ? Le message d'ouverture du ticket compte pour 1. À confirmer.
8. **Écarts de nommage** : la consigne parle de `JAP_MODE=mock`, le projet utilise `PROVIDER_MODE=mock` (utilisé). `API_SPEC §8` ne liste pas `daily_spend_limit_xaf` dans le PATCH client : ajouté (décision du propriétaire) ; l'écriture d'audit `update_user` / `add_note` est testée bien que le journal complet soit en phase 12.
9. Parcours complet e2e (mot de passe, 2 appareils, code, tableau de bord) non écrit : demande un vrai compte admin et un générateur de code TOTP ; prévu en 11.5 (QA). Le test d'inscription qui stocke `hashIp(ip)` (et jamais l'IP brute) dans `signup_ip_hash` est à ajouter par lp-coder avec le code d'inscription.
