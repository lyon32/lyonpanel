## Points pour lp-coder (appels RPC, erreurs renvoyées)
- Tous les appels : `createAdminClient().rpc(nom, { p_… })`. Erreurs lues dans `error.message` (code en toutes lettres).
- Remboursement : `refund_order({ p_order, p_amount, p_admin, p_reason, p_idem_key })`. Le résultat est la commande. Total remboursé = somme des lignes `refund` (ou `audit_log.details.total_refunded_xaf`). Erreurs : `NOT_ADMIN`, `REASON_REQUIRED`, `ORDER_NOT_FOUND` (404), `ALREADY_REFUNDED` (409), `ORDER_NOT_REFUNDABLE` (409), `AMOUNT_TOO_HIGH` (422). Montant refusé en base : 0, négatif, supérieur au plafond restant. Tout code d'erreur absent d'`api-error.ts` doit y être ajouté (ex. `ALREADY_RESENT` 409).
- Annulation admin : 1) `claim_order_cancel({ p_order, p_admin })` (`ORDER_NOT_CANCELLABLE`, `ACTION_IN_PROGRESS` : les deux en 409, aucun appel fournisseur) ; 2) `provider.cancel(provider_order_id)` ; 3a) accepté : `cancel_order({ p_order, p_admin, p_reason })` ; 3b) refusé ou panne : `release_order_cancel({ p_order, p_admin })` puis 409 `ORDER_NOT_CANCELLABLE` ou 5xx. Si `cancel_order` échoue (trace en échec), la réservation reste jusqu'à `release_order_cancel` ou 2 minutes : appeler `release_order_cancel` dans ce cas aussi.
- Renvoi : 1) `claim_order_resend({ p_order, p_admin, p_reason })` (`ALREADY_RESENT`, `ORDER_NOT_RESENDABLE`, `REASON_REQUIRED`, `ORDER_NOT_FOUND`) ; 2) `provider.add` une seule fois ; 3) `resend_order({ p_order, p_admin, p_reason, p_provider_order_id })`. Si `provider.add` échoue, `resent_at` reste posé : plus de renvoi possible, voulu (« aucune reprise automatique »). La réservation précède `add` : c'est ce qui garantit un seul appel en double clic.
- Clôture : `close_order({ p_order, p_admin, p_reason })` (`ORDER_NOT_CLOSABLE`).
- Services : `update_service({ p_service, p_admin, p_changes })` ; `confirm` et l'aperçu restent côté serveur (l'aperçu se calcule avec la même formule, ou via le module `compute-price`). Erreurs : `SERVICE_NOT_FOUND`, `INVALID_FIELD`, `EMPTY_CHANGES`.
- Réglages : `update_setting({ p_changes, p_admin })` renvoie tous les réglages en jsonb (le serveur doit retirer toute clé non listée avant de répondre : `GET` aucun secret). Erreurs : `UNKNOWN_SETTING`, `INVALID_SETTING`, `EMPTY_CHANGES`. Zod reste la première barrière.
- Tickets : `reply_ticket({ p_ticket, p_body, p_admin })` renvoie l'id du message ; `update_ticket({ p_ticket, p_status, p_admin })`. Erreurs : `TICKET_NOT_FOUND`, `INVALID_BODY`, `INVALID_STATUS`.
- Clients : `update_user({ p_user, p_admin, p_changes })` (clés `status`, `blocked_reason`, `custom_discount_pct`, `daily_spend_limit_xaf` ; erreurs `USER_NOT_FOUND`, `FORBIDDEN`, `REASON_REQUIRED`, `INVALID_FIELD`, `EMPTY_CHANGES`) ; `add_note({ p_user, p_admin, p_body })` (renvoie l'id ; `INVALID_BODY`, `USER_NOT_FOUND`). Relire ensuite la fiche avec la liste blanche de colonnes.
- Statut client après remboursement partiel : la commande reste `to_review` ; « remboursé partiellement : X XAF » se calcule avec la somme des lignes `refund` du client (la note de ces lignes est `refund_by_admin`, sans mention de paiement externe).
- Les commandes `refund_canceled_order` (annulation client) sont inchangées : même table de lignes `refund`, `ref = refund:<order>`.
